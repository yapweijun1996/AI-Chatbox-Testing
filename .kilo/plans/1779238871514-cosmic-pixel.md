# Implementation Plan: Apple-Style Serverless AI Chatbox

本方案旨在指导如何从零构建一个基于 **React (Vite) + Tailwind CSS / Native CSS + Vercel AI SDK** 的 **Apple 风格无服务器隐私安全 AI 聊天网页**。整个架构将遵循 Apple 人机交互指南 (HIG - Human Interface Guidelines)，并采用用户自备密钥 (BYOK - Bring Your Own Key) 模式，通过客户端存储或无状态边缘函数 (Edge Functions) 实现极速流式对话。

---

## 1. 技术栈与架构选型 (Tech Stack & Architecture)

### 1.1 前端核心
* **框架 (Framework)**: Vite + React (TypeScript / JavaScript)。
* **样式 (Styling)**: 原生 CSS 变量 (Native CSS Variables) 结合 Tailwind CSS，精确实现 Apple 特有的磨砂玻璃拟态、1px 极细微半透明边框及弹簧曲线动画。
* **状态管理 (State)**: Zustand (轻量化客户端状态管理)，负责管理用户的提供商配置、API Key、偏好设置与历史对话。
* **AI 交互 (AI Core)**: Vercel AI SDK (`@ai-sdk/react` + `@ai-sdk/openai` 等)。

### 1.2 服务端/中转层
* **无状态边缘路由 (Stateless Edge Functions)**: 部署于 Vercel 的 `/api/chat`。该函数**不存储任何密钥**，仅通过客户端在 Request Header 中传入的临时密钥，动态初始化大模型实例并以流式数据 (Stream Data) 格式返回给前端。

## 2. 详细实施阶段规划 (Phased Roadmap)

### Phase 1: 项目基础建设与 Apple 视觉系统建立 (Visual Framework Setup)
* **Goal**: 搭建 Vite + React 干净脚手架，定义完美的 HIG 设计变量。
* **实现步骤**:
  1. 初始化 Vite React 工程，并配置基础目录结构。
  2. 定义两套核心主题对应的 CSS 变量 (浅色 / 深色模式)：
     - **背景层**: 非单色微渐变，浅色 `#FFFFFF` 渐变至微蓝，深色 `#1C1C1E`。
     - **磨砂玻璃 (Glassmorphic)**: `backdrop-filter: blur(25px) saturate(180%)`，配合半透明背景色。
     - **超椭圆 (Squircle Borders)**: 统一圆角比例，主体容器 `20px`，消息气泡 `12px`。
     - **动效弹簧曲线**: `transition: all 0.3s cubic-bezier(0.25, 1, 0.5, 1)`。
  3. 引入 Apple 系统字体集：`system-ui, -apple-system, BlinkMacSystemFont`。

### Phase 2: 双栏/三栏响应式自适应布局 (Responsive Layout & Component Decomposition)
* **Goal**: 完成无缝自适应的 Apple 主界面框架。
* **组件设计**:
  1. **Sidebar (左侧边栏)**:
     - 顶部：无边框极简加号“新对话 (New Chat)”按钮，附带 Hover 微调缩放动效 (1.02x)。
     - 中部：历史会话列表，激活态采用半透明高亮。
     - 底部：深浅色主题一键切换、配置抽屉开关。
  2. **Main Chat Area (核心聊天区)**:
     - 顶部：`Status Pill` (状态胶囊)，包含绿色呼吸灯 (Connected) / 闪烁黄色灯 (Generating...)。
     - 中部：流式对话框。
     - 底部：`Floating Input` (浮动卡片输入框)，支持多行自适应高度，右侧圆形发送按钮内置置灰逻辑。
  3. **Settings Overlay (配置抽屉)**:
     - 采用右侧 Slide-over (滑出式弹窗)。
     - 分设 OpenAI, Google Gemini, Anthropic, LM Studio 的切换标签页 (Tab)。

### Phase 3: 安全密钥存储与加密层设计 (BYOK & Security Layer)
* **Goal**: 实现高水准的用户密钥安全防范。
* **实现步骤**:
  1. 密钥持久化：由 Zustand 同步到 `localStorage` 中。
  2. **XSS 防范混淆 (XSS Mitigation)**: 在将密钥写入 LocalStorage 前，使用客户端轻量级混淆算法（例如 Base64 变异或简易 XOR 密钥混淆），防止在发生依赖链注入攻击时，攻击者使用简单的控制台脚本轻松盗取明文。
  3. 页面内容安全策略 (CSP) 头部推荐，确保第三方脚本无法向未知非法域名发送敏感数据。

### Phase 4: Vercel AI SDK 边缘流式中转 (Edge Function & Streaming)
* **Goal**: 实现零成本、防跨域的安全中转路由。
* **实现步骤**:
  1. 在 `/api/chat` 创建 Edge Runtime 函数。
  2. **动态提供商工厂 (Dynamic Provider Factory)**: 读取传入的 `x-provider`，根据客户端发来的 `x-api-key` 和 `x-base-url` 动态创建对应的 OpenAI、Gemini 或 Anthropic 实例。
  3. **零日志留存 (Zero Logs Retention)**:
     - 绝对禁止在 Edge Function 服务端输出或记录 Request Headers 里的 `x-api-key` 明文日志。
  4. 支持跨域控制 (CORS)，在函数头中严格绑定前端发布域名，防止中转路由被第三方滥用盗刷。

### Phase 5: 高级交互细节与 Markdown 精细润色 (Details & Markdown Renderer)
* **Goal**: 达到原生 Apple 水准的渲染品质。
* **实现步骤**:
  1. **Markdown 解析**: 渲染大模型返回的流式文本，高精准度适配 LaTeX 数学公式和表格。
  2. **代码块增强**: 代码语法高亮，每个代码块右上角自带 Apple 风格的“一键复制”圆角按钮及成功反馈。
  3. **骨架流光动效**: 等待第一响应时，显示骨架屏与毛玻璃过渡扫光效果。

## 3. 验收标准与防御测试方案 (Defense Validation & Testing Plan)

为确保该无服务器应用的安全与流畅，我们将通过以下指标进行自我循环校验：

| 校验项 | 测试逻辑 (Validation Logic) | 预期结果 (Expected Result) |
| :--- | :--- | :--- |
| **视觉一致性** | 检查所有卡片、弹出框的圆角和磨砂透明边框。 | 严格符合 Apple HIG squircle 与 `0.5px` 极细微半透明边框。 |
| **XSS 盲测防御** | 模拟控制台执行 LocalStorage 明文读取脚本。 | 读取结果为加密混淆后的密文，无法直接拿到明文 Key。 |
| **CORS 安全边界** | 从非白名单域名伪造 Origin 头部向 `/api/chat` 发起 POST。 | 边缘中转路由直接拦截并返回 `403 Forbidden`。 |
| **日志防泄漏** | 故意制造一个错误调用，观察 Vercel Serverless Logs。 | 日志仅包含错误码与提供商代号，绝对没有任何 `x-api-key` 数据暴露。 |
| **流式流畅度** | 使用 Network 模拟 (G3/Slow) 检查前端数据包拼接。 | 数据流平滑渲染（Pill 灯呈现黄色 Generating），无页面阻塞或字词闪烁。 |
